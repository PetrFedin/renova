# Renova Release Quality Gates

## Purpose

Define minimum quality checks before accepting a polished product version.

## UX gates

- Core scenarios complete without confusion.
- Primary actions are obvious.
- Destructive operations are protected.
- Empty and error states provide recovery.

## Visual gates

- Shared components are used consistently.
- No unnecessary card stacking.
- Typography follows system hierarchy.
- Spacing and touch targets are predictable.

## Product gates

- First screen communicates value.
- Complex workflows are progressively disclosed.
- User confidence increases after each action.

## Review decision

A surface is ready when it is:

- understandable;
- consistent;
- actionable;
- trustworthy.

## Principle

A release is not complete when features exist. It is complete when users can operate them confidently.

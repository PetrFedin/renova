# Renova: изображения, медиа и визуализации

Дата: 2026-10-15. Источник: опубликованный клон (`main` + пакет документов, коммит `0af2d24`), только чтение; подсчёты `git ls-files`, `stat`, `sips`, `strings`, `grep`. Приложение не запускалось, скриншотов нет. Сокращения: `M/` = `apps/mobile/`, `B/` = `backend/app/`.

Ограничение: Renova операционный продукт, а не витрина. Основной «визуальный» контент создают пользователи (фото этапов, дефектов, чеки, документы), поэтому главная работа по медиа это хранение, доступ, вес и персональные данные, а не дизайн картинок. Рекомендации идут через канон (`renova-design-system.mdc`: иконки только Ionicons, без emoji, цвета только токены).

## 4. Правила для изображений и медиа в Renova

1. Форматы: JPEG и WebP для фото, PNG для скриншотов и схем; HEIC принимать только если декодер сервера его поддерживает (иначе отклонять на входе с понятным сообщением).
2. Ленивая загрузка: списки фото этапов и чатов не должны грузить полноразмерные файлы; нужны миниатюры (сервер сейчас отдаёт один размер); `expo-image` в зависимостях нет, используется `Image` React Native.
3. Alt: у каждого содержательного изображения `accessibilityLabel` с объектом и контекстом; декоративные помечать как скрытые от VoiceOver.
4. Права: источник и право использования фиксировать в реестре; пользовательские фото принадлежат пользователю, платформа получает право хранить и показывать участникам проекта (текст соглашения нужен юристу).
5. ПДн на фото: лица, номера машин, документы, чеки с картами; при публичных местах (портфолио, листинг) маскировать; при удалении аккаунта и проекта удалять и объекты хранилища (#319, `account_purge_service.py`).
6. Доступ: все объекты только по авторизованным ссылкам (`/api/v1/media/...`), предварительные ссылки короткоживущие (`presigned_put` по умолчанию 900 секунд).
7. Вес: цель ≤ 400 КБ на фото в чате и ≤ 1 МБ на фото этапа; видео не поддерживать.
8. Цвет и контраст: любые графики используют токены; «успех/предупреждение/ошибка» дублируются словом; граница карточки 1.23:1 допустима как декоративная, граница поля нужна 3:1 (см. `DESIGN.md`).
9. Диаграммы и инфографика в документации: Mermaid или SVG из токенов, без эмодзи.

## 5. Плотность и состояния

- Размеры шрифта: 14 px body и 12-13 px вторичный текст, 10-11 px служебный. Для приложения с деньгами это плотно; тесты e2e плотности есть (`e2e/responsive-kpi-density.spec.ts`).
- Пустые/ошибочные/загрузка: компоненты есть; `LoadErrorState` делает свои `PrimaryButton` (два, нарушает «1 primary CTA», если «Повторить» и «Написать в чат» оба `primary`: второй задан `outline`, значит правило соблюдено).
- Stale-состояние: `DataStatusBanner.tsx`, `OfflineSyncBanner.tsx` есть; но аудит F04 показывает, что устаревший кэш может получить метку свежего. Это ошибка данных, не оформления, но влияет на доверие к цифрам.
- Деньги: `formatRub` без дробной части; для столбцов сумм не задана табличная форма цифр (`fontVariant: ['tabular-nums']` не найден). Рекомендация в §6.

## 7. Приоритеты и порядок

1. U1-U3 (контраст, токены): малые PR, максимальный эффект для доступности.
2. U6 и U5 по экранам Dock (Главная, Объект, Ремонт, Бюджет, Сообщения), затем остальные.
3. U4, U7, U8.
4. U9-U12 после решения владельца.

Критерий для каждой волны: нет роста счётчика hex/emoji (ratchet), `npm run typecheck:mobile` и e2e responsive зелёные, один primary CTA на экран, живая спецификация (`SCREEN-CONTRACT-CATALOG.md`) синхронизирована, если меняется экранный контракт (AGENTS.md §1).

## 8. Как проверять контраст всех пар токенов

Предложение (скрипт вне репозитория или как часть существующего `ci.yml`, мандат запрещает новые workflow):

1. Прочитать `RenovaTheme.colors` (импорт через tsx).
2. Задать матрицу «текст × поверхность» из реального использования: text, textMuted, textSubtle, inverseText, accent, successText, warningText, dangerText, infoText, neutralText × background, surface, surfaceMuted, accentMuted, successBg, warningBg, dangerBg, infoBg, neutralBg, primary, accent, danger.
3. Считать отношение по WCAG, вывести таблицу, падать, если пара, помеченная как «текст», ниже 4.5 (крупный 3.0; нетекстовые 3.0).
4. Добавить список разрешённых исключений с причиной (декоративные границы).
5. Запускать как шаг существующего ci.yml (мандат §1.5: без нового workflow) и локально.
6. Дополнить ручной проверкой на устройстве (VoiceOver, крупный шрифт, режим тёмной темы).

## Что осталось неподтверждённым

- Как экраны выглядят на устройстве: скриншоты и запуск не выполнялись.
- Реальное число нарушений «один primary CTA на экран» и «самодельные карточки»: автоматического счётчика нет.
- Часть из 47 «emoji» может быть типографскими символами (✓, ⚠); требуется ручная классификация.
- Фактическая работа тёмной темы на устройстве.
- Соответствие нижней панели (`OsDockBar`) меткам доступности.

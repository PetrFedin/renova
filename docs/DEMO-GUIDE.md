# Renova: руководство по демонстрации инвесторам

Документ для того, кто показывает продукт: как поднять стенд, как войти, что говорить и нажимать за 10–15 минут, чего не трогать, что в демо честно является заглушкой, как вернуть стенд в исходное состояние и что отвечать на вопросы инвесторов.

Правило документа то же, что у `PRODUCTION-READINESS.md`: «готово» пишется только там, где это подтверждено кодом или выполненной проверкой. Всё, что не доказано, названо заглушкой или целью. Цифр, которых нет в `PRODUCTION-READINESS.md` и `docs/INTEGRATIONS.md`, здесь нет и на показе называть их нельзя.

Проверено вживую 2026-10-04 на локальном стенде (API `127.0.0.1:8100`, Expo web `127.0.0.1:8081`, версия `0.3.7`). Что именно прошли и что оказалось неудобным, описано в разделе 9.

Содержание:

1. Что показываем в одной фразе
2. Поднять стенд
3. Демо-учётки и вход
4. Подготовка перед показом (за день и за час)
5. Сценарий на 10–15 минут
6. Чего не нажимать
7. Что в демо является заглушкой
8. Сбросить демо в исходное состояние
9. Что может подвести на показе (по результатам живой проверки)
10. Частые вопросы инвесторов и честные ответы
11. Чек-лист перед показом (5 минут)

---

## 1. Что показываем в одной фразе

Renova ведёт ремонт квартиры от сметы до приёмки и оплаты в одном приложении для двух сторон: заказчик и исполнитель видят одни и те же данные. Договорённость (смета, договор, график, приёмка, платёж) фиксируется в системе, а не в переписке и Excel.

Проблема, с которой начинается показ: ремонт живёт в Excel, мессенджерах и банковских переводах. Смета меняется без следа, акты и фото теряются, непонятно, что уже оплачено и принято, а спор о деньгах нечем доказать.

Решение, которое вы показываете: единая цепочка «объект → смета → фиксация сметы → исполнитель → договор с двумя подписями → график → этапы → приёмка с фото → платёж → план–факт бюджета», где каждое действие одной стороны сразу видно другой, а деньги попадают в факт только после подтверждения.

Важно для честного рассказа: приложение сделано на Expo (React Native). Для показа используется веб-сборка в браузере в «телефонной» ширине. Сборки для App Store и Google Play нет (блокер E5 в `PRODUCTION-READINESS.md`).

## 2. Поднять стенд

Стенд полностью локальный. Он не обращается к внешним провайдерам: канонический локальный профиль отказывается стартовать, если в `.env.local` заданы реальные ключи платежей, SMS, НПД, почты и так далее (`scripts/dev-runtime.sh`, функция `assert_no_external_local_configuration`). Это сделано намеренно, чтобы демо никогда не списало деньги и не отправило SMS.

### 2.1. Что должно быть установлено

| Что | Версия | Проверка |
|---|---|---|
| Docker (Compose v2) с локальным демоном | любой свежий | `docker compose version` |
| Node.js | 20.x | `node -v` |
| Python | 3.12.13 | `python3 --version` |
| Poetry | 2.4.1 | `poetry --version` |
| Свободные порты | 8100 (API), 8081 (Expo web), 5433 (PostgreSQL), 6380 (Redis), 9000 и 9001 (MinIO) | `lsof -nP -iTCP:8100 -sTCP:LISTEN` и так же для остальных |

Если порт занят чужим процессом, не останавливайте чужое. Либо освободите порт, либо проверьте, что на нём уже стоит именно стенд Renova (раздел 2.4).

### 2.2. Рекомендуемый путь: канонический скрипт `npm run dev`

Все команды выполняются из корня репозитория `/Users/petr/renova`. Скрипт `scripts/dev-runtime.sh` описан в `docs/DEVELOPMENT-CANON.md`, раздел 5.

1. Установить зависимости один раз (повторять только после обновления кода):
   ```bash
   cd /Users/petr/renova
   npm run dev -- bootstrap
   ```
   Это `npm ci` и `poetry install` по lock-файлам. Обычный запуск зависимости сам не ставит.
2. Проверить инструменты и локальный профиль:
   ```bash
   npm run dev -- doctor
   ```
   Если нет файла `.env.local`, скрипт сам скопирует `env.local.example`. Содержимое примера уже правильное для демо: `ENVIRONMENT=development`, `ALLOW_DEMO_SEED=true`, `EXPO_PUBLIC_DEMO=1`, `EXPO_PUBLIC_API_URL=http://127.0.0.1:8100`, все внешние ключи пустые.
3. Поднять всё одной командой:
   ```bash
   npm run dev
   ```
   Что происходит по порядку: PostgreSQL, Redis и MinIO стартуют и ждут `healthy`; выполняется `alembic upgrade head` (миграции) с жёсткой остановкой при ошибке; проверяется, что база ровно на head; поднимаются контейнеры `api` и `worker`; проверяются `/health`, `/ready` и пульс worker; затем в этом же терминале в переднем плане стартует Expo web на порту 8081. Терминал нельзя закрывать, пока идёт показ.
   Если нужен только backend без Expo: `RENOVA_DEV_NO_EXPO=1 npm run dev`.
4. Дождаться строки Expo с адресом `http://localhost:8081` и открыть её в браузере (раздел 2.5).
5. Убедиться, что всё живо:
   ```bash
   npm run dev -- check
   ```
   Команда возвращает ненулевой код, если инфраструктура, миграции, API, worker или адрес API в мобильном приложении не в порядке.

### 2.3. Миграции и demo-данные по отдельности

- Миграции выполняются автоматически на шаге 3 выше. Вручную в контейнерном стенде это отдельный сервис compose: `docker compose -p renova-local run --rm migrate`. На хосте без контейнеров: `bash scripts/migrate.sh` (активирует `backend/.venv` и делает `alembic upgrade head`). Новые миграции для демо создавать не нужно.
- Демо-данные (учётки и объекты) создаются при старте API, пока `ALLOW_DEMO_SEED=true` (так в `env.local.example`). Принудительно и идемпотентно:
  ```bash
  npm run dev -- seed
  ```
  Команда выполняет `python -m app.dev_seed` внутри контейнера `api` и безопасна для повторного запуска.
- В рабочих средах (staging, production) demo-seed запрещён и валит старт. Демо-стенд никогда нельзя собирать в такой профиль.

### 2.4. Если API запущен на хосте, а не в контейнере

Допустимый вариант для разработчика: PostgreSQL, Redis и MinIO из compose (`npm run dev -- infra`), backend отдельно.

```bash
npm run dev -- infra          # PostgreSQL + Redis + MinIO
bash scripts/migrate.sh       # миграции
npm run backend:dev           # API на :8100 (poetry run uvicorn app.main:app --reload --port 8100)
npm run dev:worker            # worker в соседнем терминале; без него не работают напоминания, outbox и сверка провайдеров
cd apps/mobile && npm run web -- --port 8081
```

Запускайте либо worker на хосте, либо контейнерный worker, не оба сразу (`docs/DEVELOPMENT-CANON.md`).

### 2.5. Открыть приложение

1. Откройте в Chrome адрес `http://localhost:8081`.
2. Откройте инструменты разработчика (`Cmd+Option+I`), включите режим устройства (`Cmd+Shift+M`), выберите ширину около 430 пикселей (например iPhone 14 Pro Max) или просто сузьте окно до 430 пикселей. Интерфейс рассчитан на телефон; на широком экране он растягивается и выглядит хуже.
3. Первая загрузка в режиме разработки медленная: Metro собирает пакет. Дождитесь, пока пропадёт спиннер, и только потом начинайте показ. Перед показом откройте приложение заранее и один раз пройдите по главным вкладкам, чтобы пакет был прогрет.

### 2.6. Остановить

```bash
npm run dev -- stop      # останавливает контейнеры и host-worker, данные в томах остаются
```

Команда `npm run dev -- reset` уничтожает локальные тома стенда (раздел 8). Во время подготовки к показу её не запускайте.

## 3. Демо-учётки и вход

Регистрации по SMS для демо не нужно. Демо-вход выдаёт заранее созданные учётки, и он включён только при `EXPO_PUBLIC_DEMO=1` (по умолчанию демо-вход скрыт, так сделано специально). После изменения `.env.local` Expo нужно перезапустить: переменные `EXPO_PUBLIC_*` вшиваются в пакет при сборке.

| Роль | Имя в приложении | Телефон | Кнопка на экране входа | Что видит |
|---|---|---|---|---|
| Заказчик | Демо заказчик | `+70000000001` | «Заказчик» | Свои объекты, смету, платежи, приёмку, чат, клиентский портал, гостей |
| Исполнитель | Демо Подрядчик Renova | `+70000000002` | «Исполнитель» | Объекты, где он назначен: строки сметы, график, этапы, фото, заявки на оплату |
| Гость (только чтение) | Демо гость (read-only) | `+70000000003` | нет кнопки в интерфейсе | Объекты, куда заказчик добавил его как наблюдателя; запись запрещена сервером |
| Администратор | любой user id из `ADMIN_USER_IDS` | — | — | Центр администратора (раздел 5, шаг 15) |

### 3.1. Как войти без регистрации

1. Откройте `http://localhost:8081`. Если вы уже входили, выйдите: «Профиль» → «← Выбор роли» (он же «Выйти из аккаунта и войти заново»).
2. На экране «Кто вы в этом проекте?» вверху должны быть две вкладки: «Демо-стенд» и «SMS». Выберите «Демо-стенд». Под ней подпись «Демо-вход создаёт учебные данные. Для пилота используйте SMS.» Если вкладки «Демо-стенд» нет, значит `EXPO_PUBLIC_DEMO` не равна 1 (раздел 2.2, шаг 2).
3. Нажмите «Заказчик» или «Исполнитель», затем «Продолжить».
4. На экране «Как показывать информацию?» выберите «Стандарт» и нажмите «Продолжить» (при первом входе под этой учёткой на этом браузере).
5. На экране «Выберите объект» нажмите на нужный объект. Для готовой витрины это «Демо-квартира, ул. Пример 12». Для показа создания с нуля нажмите «Создать объект» (раздел 5, шаг 2).
6. Сменить роль можно в любой момент: «Профиль» → «← Выбор роли» → выбрать другую роль.

### 3.2. Две роли одновременно

Чтобы показать, что действие одной стороны сразу видно другой, нужны две независимые сессии. Данные сессии хранятся в localStorage браузера, поэтому в одном профиле Chrome вторая вкладка разделит сессию с первой. Используйте:

- окно обычного Chrome для заказчика и окно в режиме инкогнито для исполнителя, либо
- два разных профиля Chrome.

Расположите окна рядом, у каждого ширина около 430 пикселей. Так инвестор видит обе стороны сразу.

### 3.3. Вход по SMS (если нужен «боевой» вид)

На вкладке «SMS» введите телефон, нажмите «Отправить код». В режиме разработки сервер возвращает код прямо в приложении («Демо-код: …»), реального SMS не уходит. В staging и production такого предпросмотра нет, а без настроенного Twilio сервис не стартует. Это нужно проговорить, если показываете вход по SMS.

### 3.4. Ловушки названий объектов

- Приложение считает мусором и не делает активными объекты, в названии которых есть `e2e`, `wizard test`, `gate test`, `walkthrough`, слово `test`, а также просто «Студия». Под демо-учёткой такой объект создаётся, но Renova тут же оставляет открытым «Демо-квартиру» (в окне будет сообщение «На демо открыт «Демо-квартира…» — переключите объект в шапке»). Для показа называйте объект по-человечески: «Квартира Иванова», «Ремонт на Тверской».
- Очистка мусора (`backend/scripts/cleanup_e2e_demo_data.py`) считает мусором объекты с названием «E2E…» и объекты, у которых адрес начинается с `E2E`. Свои показные объекты не называйте так и не пишите такой адрес, иначе они попадут в чистку.

## 4. Подготовка перед показом

### 4.1. Как устроить показ, чтобы уложиться в 10–15 минут

Показ с нуля от пустого объекта до оплаты за 15 минут не получается, если делать всё руками на медленном стенде. Поэтому используйте два объекта:

- **Живой объект, который вы создаёте на глазах у инвесторов** (шаги 2–7): создание, смета, подключение исполнителя, фиксация, договор, график, первый этап, приёмка. Название у него человеческое, например «Квартира Иванова».
- **Готовая витрина «Демо-квартира, ул. Пример 12»** (шаги 8–15): в ней уже есть 3 комнаты, 8 этапов, смета на 185 938 ₽, назначенный исполнитель, этап, ожидающий приёмки, два неоплаченных счёта, чаты с карточками действий и гости. Её удобно использовать для платежей, материалов, чата, портала и уведомлений, потому что там есть что смотреть.

Важно: действия на «Демо-квартире» меняют её. Принятый этап нельзя «разпринять», подтверждённую подпись нельзя снять. Если нужно показывать с этого объекта приёмку, после показа сбросьте стенд (раздел 8).

### 4.2. За день до показа

1. Обновить код и зависимости, поднять стенд (раздел 2), прогнать чек-лист из раздела 11.
2. Пройти весь сценарий (раздел 5) один раз целиком под обеими ролями. Это прогревает пакет Metro и показывает, где стенд сегодня тормозит.
3. Убрать накопившийся мусор в демо-аккаунте (раздел 8.2). На общем dev-стенде под одним демо-заказчиком копятся десятки проектов от автотестов: они засоряют список объектов, уведомления (счётчик «99+» на колокольчике) и чаты.
4. Решить, что вы показываете на «Демо-квартире», и сбросить стенд, если на ней уже кто-то принимал этапы или платил.

### 4.3. За час до показа

1. Прогнать чек-лист из раздела 11 (5 минут).
2. Открыть два окна Chrome по 430 пикселей: обычное для заказчика, инкогнито для исполнителя. Войти в обе роли (раздел 3.1 и 3.2) и один раз открыть главные вкладки: «Главная», «Объект», «Ремонт», «Деньги», «Сообщения».
3. Закрыть лишние вкладки и приложения: стенд работает на вашей же машине, и перегруженный компьютер замедляет все экраны. На нагруженной машине экраны «Деньги» и «Приёмка» грузились десятки секунд (раздел 9).
4. Отключить уведомления macOS и мессенджеры, чтобы они не всплыли на демонстрации экрана.

## 5. Сценарий на 10–15 минут

Порядок: проблема, затем решение шаг за шагом. Время указано ориентировочное, всего около 14 минут при неспешном рассказе; быстрый вариант на 10 минут отмечен в конце раздела.

Условные обозначения в каждом шаге:

- **Окно** — какая роль и какой объект.
- **Нажимать** — точная последовательность.
- **Видно** — что должно появиться на экране.
- **Ценность** — что сказать инвестору.
- **Не нажимать** — что рядом опасно.
- **Честно** — что в этом шаге является заглушкой или не доказано.

### Шаг 1. Проблема и решение (0:00–1:30)

- **Окно:** экран входа, роль ещё не выбрана.
- **Говорите:** ремонт ведут в Excel, мессенджерах и переводах на карту. Смета меняется без следа, фото и акты теряются, непонятно, что оплачено и что принято. Мы собрали одну цепочку, где каждый шаг подтверждает вторая сторона.
- **Нажимать:** на экране «Кто вы в этом проекте?» вкладка «Демо-стенд» → «Заказчик» → «Продолжить» → «Стандарт» → «Продолжить».
- **Видно:** экран «Выберите объект» со списком объектов.
- **Честно:** демо-вход существует только на стенде разработки (`EXPO_PUBLIC_DEMO=1`). В реальном продукте вход по SMS.

### Шаг 2. Заказчик создаёт объект и комнаты (1:30–3:00)

- **Окно:** заказчик, «Выберите объект».
- **Нажимать:**
  1. «Создать объект».
  2. В поле «Название» ввести «Квартира Иванова», в «Адрес» любой адрес. Не используйте слова `test`, `e2e`, «Студия» (раздел 3.4).
  3. Вверху выбрать «Быстро (~1 мин)». По умолчанию мастер открывается в режиме «Подробно».
  4. В поле «Общая площадь, м²» оставить значение по умолчанию или ввести своё.
  5. «К смете».
  6. Прокрутить экран «Быстрая смета»: сумма, план работ, список комнат с размерами, блок «Бюджет заказчика» (лимит, который приложение будет контролировать), блок «Рыночная оценка».
  7. «Создать проект».
  8. В окне «Объект создан» нажать «Закрыть» (или «На главную»).
  9. Внизу «Объект» → вкладка «Комнаты».
- **Видно:** сумма сметы, пять комнат (Гостиная, Кухня, Прихожая, Санузел, Спальня) с площадями; на «Главной» карточка «Настройка объекта» с чек-листом: «Объект создан», «Данные объекта», «Исполнитель», «Комнаты», «Смета согласована», «Этапы», «Бюджет под контролем».
- **Ценность:** за минуту получается объект, комнаты и первая смета, рассчитанная из габаритов. Дальше приложение само подсказывает следующий шаг («Очередь дел»).
- **Не нажимать:** в переключателе объектов (иконка здания в шапке) красные значки корзины и значки архива рядом с каждым объектом; пункты «Архив» и «Корзина».
- **Честно:** это расчёт по шаблону. «Рыночная оценка» и блок «Лемана ПРО — примерные позиции» показывают ориентиры, подписаны как ориентир и «не в учёт проекта», живых цен магазина нет. Если инвестор сравнит цифры: сумма «Быстрой сметы» в мастере и итог сметы уже созданного объекта могут не совпасть (в проверке 273 972 ₽ в мастере и 317 971 ₽ в объекте, раздел 9, пункт P2). Заранее решите, что вы скажете: «в мастере предварительная оценка, смета уточняется исполнителем».

### Шаг 3. Смета, подбор исполнителя и заявка, фиксация сметы (3:00–5:30)

Смету фиксирует заказчик, но предлагает зафиксировать её исполнитель. Поэтому шаг идёт в три действия, в двух окнах.

**3а. Смета (заказчик).**

- **Нажимать:** «Объект» → вкладка «Смета».
- **Видно:** «Итого по смете», строка «Черновик — сумма ещё не согласована», разбивка «Работы … (N) · Материалы … (N)», счётчики «Комнаты», «Этапы», «На согласовании», блок «Кто заполняет» (авто из комнат, правки подрядчика). Вкладки «Итог», «Изменения», «Детализация», «Документы».
- **Ценность:** смета структурирована (работы и материалы, по комнатам и статьям), а не лежит в таблице.

**3б. Подбор исполнителя и заявка.**

- **Нажимать (заказчик):** «Профиль» (иконка человека в шапке) → блок «Исполнитель». Видны «Код объекта» с кнопкой «Поделиться кодом (WhatsApp / Telegram)» и карточка «Демо Подрядчик Renova» с кнопкой «Подключить». Нажать «Подключить».
- **Видно:** исполнитель назначен, нижняя панель заказчика перестраивается под этап ремонта («Главная», «Сообщения», «Объект», «Деньги», «Ремонт»).
- **Заявка со стороны исполнителя:** второй способ — исполнитель в своём «Профиле» в блоке «Новый объект по коду» вводит код объекта и нажимает «Предложить вести проект», а заказчик подтверждает заявку («Заявки на исполнителя» в его профиле). Подробнее: исполнитель не может принять заявку сам (проверено сквозным smoke через API: 403). В интерфейсе этот второй путь при проверке не нажимался, показывайте путь «Подключить».
- **Ценность:** исполнитель появляется на объекте только по согласию заказчика; чужой исполнитель объект не видит (smoke: «outsider contractor still has no access»).
- **Не нажимать:** «Заменить исполнителя» в профиле (меняет назначение на ходу).
- **Честно:** в демо подрядчик один, подбор «по специализации» без рейтингов («Оценок пока нет»). Каталог исполнителей с рейтингами на стенде не наполнен.

**3в. Фиксация сметы.**

- **Нажимать (исполнитель, окно инкогнито):** войти как «Исполнитель», выбрать объект «Квартира Иванова» → «Объект» → «Смета» → прокрутить вниз → «Отправить смету на согласование». Появится окно «Смета у заказчика»: «Фиксацию подтверждает заказчик».
- **Нажимать (заказчик):** «Объект» → «Смета» → кнопка «Согласовать и зафиксировать смету» → в окне «Зафиксировать смету?» нажать «Зафиксировать». Ниже есть «Отклонить — нужна правка».
- **Видно:** «Согласована · зафиксирована <дата>», окно «Смета зафиксирована. Дальше — договор в Документах и согласование графика.» Базовые строки теперь нельзя свободно менять, новые работы идут через «Изменения» (дополнительные работы по согласию).
- **Ценность:** сумма сметы становится договорной величиной с датой и автором; любое расхождение потом видно.
- **Честно:** если исполнитель не отправил смету, у заказчика кнопки фиксации нет (на «Главной» написано «Смета ещё у исполнителя»). Это не поломка, так задумано.

### Шаг 4. Договор с двумя подписями (5:30–7:00)

- **Нажимать (исполнитель):** «Профиль» или главная → «Документы» (экран `/documents`; в меню «Ещё» тоже есть) → «Договор подряда» → «Подписать в приложении» → в окне «Подписать документ?» нажать «Подписать».
- **Нажимать (заказчик):** тот же путь. Сверху блок «Нужно подписать (1)».
- **Видно:** в окне подтверждения написано: «Это простая электронная подпись в приложении, не квалифицированная. После подписи документ изменить нельзя.» После первой подписи договор ещё не действует; после второй статус «Действует», окно «Подписано».
- **Ценность:** работа не начнётся без договора. Сервер не даёт стартовать этап, пока договор не подписан обеими сторонами (smoke: `stage start blocked before signatures`). Договор собирается из зафиксированной сметы автоматически.
- **Не нажимать:** в карточке документа «В архив» и «Защитить от удаления».
- **Честно:** подпись внутренняя (`in_app`). На экране есть плашки «Контур.Подпись: недоступен» и «Подпись: только в приложении». Квалифицированная подпись через Контур не подключена, Госключ не реализован (`docs/INTEGRATIONS.md`, раздел 5; `PRODUCTION-READINESS.md`, E13). Юридическую силу такой подписи оценивает юрист, не говорите, что она «как нотариальная».

### Шаг 5. График и этапы (7:00–8:30)

- **Нажимать (исполнитель):**
  1. «Сроки» (в нижней панели «Ремонт» → «Сроки» или иконка календаря) → «План-график и задачи · развернуть».
  2. «Создать план-график из этапов» → статус «черновик · 8 этапов».
  3. «Отправить заказчику на согласование».
- **Нажимать (заказчик):** «Сроки» → развернуть → «Согласовать график» → в окне «Согласовать график?» нажать «Согласовать».
- **Видно:** этапы Подготовка, Демонтаж, Черновые работы, Стены, Пол, Чистовая отделка, Приёмка, Завершение проекта с датами; статус графика «согласован».
- **Ценность:** сроки тоже договорённость, а не устная; исполнитель не может подтвердить свой график сам (smoke: `contractor cannot confirm own schedule`).
- **Честно:** экспорт в календарь — разовый `.ics`-файл для импорта в Google или Apple Calendar, а не живая синхронизация (так написано на экране). Заготовка графика строится из этапов шаблона.

### Шаг 6. Работа на этапе: чек-лист, фото до и после, сдача (8:30–9:45)

- **Нажимать (исполнитель):** «Ремонт» → вкладка «Этапы» → «Подготовка» → «Начать» → отметить пункты «Чек-лист перед сдачей» (4 пункта) → раскрыть «Фото до / после» → «До работ» (выбрать файл) → «После работ» (выбрать файл) → кнопка «На приёмку» в верхней карточке.
- **Видно:** до сдачи блок «Перед сдачей» перечисляет, чего не хватает («Чек-лист 0.0% — выполните все пункты», «Не добавлены фотографии результата»); после — статус «На приёмке: Исполнитель отметил готовность, ждёт решения заказчика».
- **Ценность:** сдать этап можно только с закрытым чек-листом и фотографиями результата; фото с подписью «До работ» и «После работ» остаются доказательством.
- **Не нажимать:** «Добавить» массовую сдачу долгим нажатием на строку этапа (выбор для массовой сдачи).
- **Честно:** фото грузятся в MinIO по подписанной ссылке (локальный S3). В production нужен управляемый S3 (блокер E6, `docs/INTEGRATIONS.md`, раздел 6).

### Шаг 7. Приёмка с фото до и после и оценкой (9:45–10:45)

- **Нажимать (заказчик):** «Ремонт» → вкладка «Приёмка» (на ней красный значок с числом) → при желании «Открыть этап» (фото до и после) → выбрать оценку 1–10 (поле необязательное, например 9) → «Принять» → в окне «Принять этап?» нажать «Принять».
- **Видно:** в окне написано «После приёмки откроется цепочка оплаты»; этап становится «done», прогресс объекта растёт (в проверке до 5 %), автоматически создаётся счёт «Оплата этапа: Подготовка» на сумму этапа (15 899 ₽), приходит уведомление, формируется акт приёмки (PDF).
- **Ценность:** приёмка — единственный момент, который порождает платёж. Исполнитель не может принять свою работу сам (smoke: `contractor cannot accept own work`), повторное нажатие «Принять» ничего не дублирует (`accept is idempotent`).
- **Не нажимать:** «Вернуть на доработку» без подготовки: она требует обязательную причину (если хотите показать доработку, заранее продумайте замечание).
- **Честно:** оценка качества необязательна, подсказка прямо говорит «только если реально проверили».

### Шаг 8. Платежи и бюджет план–факт (10:45–12:15)

- **Нажимать (заказчик):** «Деньги» → вкладка «Оплаты» → счёт «Оплата этапа: Подготовка» → «Я перевёл — приложить подтверждение» → «Выбрать файл» (любой файл-чек) → «Отправить на проверку». Затем вкладка «План–факт».
- **Нажимать (исполнитель):** «Бюджет» → «Оплаты» → строка с пометкой «Заказчик отметил перевод — подтвердите, что деньги пришли» → подтвердить получение.
- **Видно у заказчика:** до подтверждения в «План–факт» «Факт 0 ₽», «Остаток» равен плану, и отдельная строка «Не в факте: 15 899 ₽ оплачено без проверки — нужен чек или подтверждение получения исполнителем». После подтверждения исполнителем сумма попадает в факт.
- **Ценность:** это главный аргумент про «правду в деньгах». Приложение не записывает расход в факт на слово: нужен чек или подтверждение получателя, а сумма «оплачено без проверки» показывается отдельно. В карточке бюджета виден «Лимит заказчика» и контроль перерасхода (процент оповещения 5/10/15/20 % настраивается в профиле).
- **Не нажимать:** кнопки «Оплатить N ₽» на вкладке «План–факт» и в очереди дел «Оплатить 2 счёта»: они запускают оплату через ЮKassa, которой на стенде нет. Ответ checkout 503 (`docs/INTEGRATIONS.md`, раздел 1). Также не нажимайте «Импорт выписки» без подготовленного файла.
- **Честно:** деньги в Renova не двигаются. Перевод заказчик делает вне приложения (СБП, карта, счёт), в приложении фиксируется факт и доказательство. Онлайн-оплата (ЮKassa) в демо не подключена: требуется договор и боевые ключи (E2). Налог НПД («Мой налог») и проверка чеков ФНС тоже заглушки (E1).

### Шаг 9. Материалы и закупки (12:15–13:00)

- **Окно:** заказчик, объект «Демо-квартира» (в свежем объекте материалы пока не рассчитаны: «Нет потребностей — рассчитайте материалы из сметы»).
- **Нажимать:** «Ремонт» → вкладка «Материалы» → «Потребности» → «Закупки» → «Чеки». Вкладка «Подбор» (подбор материалов, который заказчик согласует перед закупкой).
- **Видно:** счётчики «Нужно купить» и «Доступно», потребности из сметы, закупки и чеки; в «Подборе» исполнитель предлагает материал, заказчик согласует.
- **Ценность:** материалы выводятся из сметы, а закупка требует согласования заказчиком: нет «самодеятельности» исполнителя на деньги заказчика.
- **Не нажимать:** «+ Материал» и «Из сметы» на «Демо-квартире» (создают записи на общем объекте).
- **Честно:** цены и каталог ориентировочные; интеграции с поставщиками нет.

### Шаг 10. Чат с действиями (13:00–13:45)

- **Окно:** заказчик, «Демо-квартира».
- **Нажимать:** «Сообщения» → фильтр «Все объекты» / выбрать «Демо-квартира» → чат «Согласование сметы» (в нём карточка «Запрос подтверждения») или «Оплата этапа «Электрика»» (карточка с фото) или чат задачи «Ванная: плитка и сантехника» («Задача: Укладка плитки в ванной»).
- **Видно:** к чату привязан объект, внутри сообщения-карточки: запрос подтверждения, задача, фото, счёт; есть закрепление сообщений, ответ на сообщение.
- **Ценность:** обсуждение и решение лежат рядом: из чата можно выставить запрос подтверждения или счёт, и они отражаются в бюджете и графике, а не теряются в мессенджере.
- **Не нажимать:** «Создать чат» на общем объекте без нужды (на общем демо-аккаунте копятся служебные чаты).
- **Честно:** это внутренний чат Renova. Прямой отправки в WhatsApp нет, только системное «Поделиться»; отдельного WhatsApp Business API в этой версии нет (так написано на экране «Профиль»).

### Шаг 11. Портал для гостя, только чтение (13:45–14:30)

- **Окно:** заказчик, затем чистое окно без входа.
- **Нажимать:** «Профиль» → «Клиентский портал» → «Поделиться ссылкой» (по умолчанию ссылка только на просмотр) → открыть выданную ссылку в окне инкогнито, где вход не выполнен. Если нужно показать гостя-наблюдателя, там же в блоке «Гости» ввести телефон и «Добавить».
- **Видно:** страница портала без входа в приложение: состояние объекта в режиме просмотра. Активные ссылки перечислены, у каждой есть «Отозвать».
- **Ценность:** родственнику или инвестору-наблюдателю не нужно ставить приложение: ссылка с ограничением по сроку (в ответе API `expires_hours` 168, то есть 7 суток) и по правам (по умолчанию `read`; приёмку, подпись и оплату заказчик включает отдельным явным действием).
- **Не нажимать:** «Отозвать» у ссылок «Демо-квартиры» (они общие), а также разрешения на приёмку, подпись и оплату в ссылке, если не готовы объяснять, что гость сможет принять этап.
- **Честно:** гость на стенде вне портала не имеет кнопки входа. Демо-учётка гостя (`+70000000003`) доступна только через API `/auth/demo/guest` и SMS. Права проверены smoke: гость не может комментировать этап и не может зафиксировать смету.

### Шаг 12. Уведомления (14:30–15:00)

- **Окно:** заказчик.
- **Нажимать:** колокольчик в шапке → «Уведомления» (счётчик непрочитанных) → прокрутить ленту. «Отметить все прочитанными» можно нажать после показа.
- **Видно:** хронология шагов по объекту: «Смета на согласование», «Документ подписан: Договор подряда», «Согласуйте план-график», «Начат этап: Подготовка», «Нужна приёмка», «Подтвердите оплату этапа», «Акт приёмки готов».
- **Ценность:** обе стороны получают событие в момент действия другой. Это то, что заменяет «напиши мне в мессенджер».
- **Честно:** это внутренняя лента. Push на телефон на стенде не работает: серверу ключи не нужны, но APNs/FCM-ключи, `projectId` EAS и живая доставка не настроены и не проверены (E4, `docs/INTEGRATIONS.md`, раздел 4). SMS на стенде не уходят вовсе.

### Шаг 13. Офлайн-очередь (15:00–15:30)

- **Окно:** исполнитель, этап в работе (например «Демонтаж»).
- **Нажимать:** открыть этап, в инструментах разработчика Chrome вкладка Network → переключатель «Offline», затем отметить пункт чек-листа. Вернуть «No throttling».
- **Видно:** окно «Нет сети»: «Действие «Отметка в чек-листе» поставлено в очередь и выполнится при появлении интернета. Не закрывайте приложение сразу.» После возвращения сети действие уходит на сервер.
- **Ценность:** на стройке нет связи; действия исполнителя не теряются и не дублируются (при повторе используется тот же идентификатор запроса).
- **Честно:** очередь работает для части действий (чек-лист, комментарии, чат и другие записи, которые помечены как ставящиеся в очередь); платёжные и юридически значимые действия в офлайне не выполняются. В проверке отметка в списке не показывается сразу, пока она в очереди (счётчик остаётся 0/5), это шероховатость, не потеря данных.

### Шаг 14. Роли и разграничение доступа (15:30–16:15)

- **Нажимать:** покажите три факта.
  1. Заказчик открывает Центр администратора напрямую по адресу `http://localhost:8081/admin-dashboard` (кнопки «Админ: статистика» и «Админ: панель» есть только в профиле исполнителя и только у администратора). Видно «Нет доступа. Этот раздел доступен только администраторам.»
  2. Исполнитель на смете видит «Отправить смету на согласование», но не кнопку «Зафиксировать»: фиксирует только заказчик.
  3. Исполнитель в окне инкогнито не видит чужие объекты: без назначения объект ему недоступен.
- **Ценность:** права проверяет сервер, а не только скрытые кнопки. На сервере: исполнитель не может принять свою работу, подтвердить свой график, подтвердить платёж; гость не может писать (все пункты проверены сквозным smoke, `scripts/release-smoke.py`). Чужой объект отвечает 404, а не 403, чтобы не раскрывать, что он существует.
- **Честно:** проверку доступа на уровне интерфейса и API мы показываем на стенде; независимый пентест и ревью привилегированного доступа ещё не проводились (E11).

### Шаг 15. Центр администратора и статус интеграций (16:15–17:00, по желанию)

- **Условие:** администратором считается только пользователь из `ADMIN_USER_IDS`. В стандартном локальном профиле список пустой, поэтому «Админ» показывает «Нет доступа» (это шаг 14). Чтобы показать центр, до показа вписать id демо-исполнителя (кнопки администратора есть только в профиле исполнителя) в `ADMIN_USER_IDS` в `.env.local` и перезапустить API.
  1. Узнать id: `curl -s -X POST http://127.0.0.1:8100/api/v1/auth/demo -H 'content-type: application/json' -d '{"role":"contractor"}'` — в ответе поле `id` (токен в отчётах не светите).
  2. Вписать `ADMIN_USER_IDS=<id>` в `.env.local`, затем `npm run dev -- stop` и `npm run dev`.
- **Нажимать:** под администратором-исполнителем «Профиль» → «Админ: панель» (панель с состоянием: статус, доставка событий, SMTP, worker, ФНС, Контур, строка «H0 investor: READY/NOT READY» с блокерами). Из терминала: `RENOVA_API_URL=http://127.0.0.1:8100 RENOVA_ADMIN_TOKEN=<токен> python3 scripts/integrations-status.py`.
- **Видно:** реестр из 10 интеграций (платежи, НПД, чеки ФНС, SMS, push, e-sign, S3, email, Sentry, OTLP) со статусами `stub`, `configured`, `partial` или `external_only`, списком недостающих ключей и пометкой `live_verified=false`.
- **Ценность:** продукт сам честно говорит, что в нём заглушка, а что настроено; в production стартовать без обязательных интеграций он отказывается (fail-closed).
- **Честно:** зелёный статус означает «конфигурация полная», а не «провайдер реально отвечает». На стенде почти всё `stub`, это ожидаемо. При настройке из репозитория вы увидите тот же список: в локальном профиле S3 (MinIO) настроен, остальное заглушки; push `external_only`.

## 6. Чего не нажимать

Это правила безопасности показа. Они касаются необратимых действий и тех, что меняют общий демо-аккаунт.

| Где | Что | Почему |
|---|---|---|
| «Профиль» → «Безопасность» | «Удалить аккаунт» | Удаляет демо-учётку заказчика или исполнителя; общий аккаунт будет сломан |
| «Профиль» → «Безопасность» | «Выйти на всех устройствах» | Разлогинит вторую роль и всех, кто сидит под тем же аккаунтом |
| Переключатель объектов (иконка здания) | красная корзина и значок архива у объекта, вкладки «Архив», «Корзина» | Убирает объект с глаз; чужие объекты общего аккаунта трогать нельзя |
| «Документы» → карточка | «В архив», «Защитить от удаления», «Распознать тип документа» | Меняет состояние документа на общем объекте |
| «Профиль» → «Клиентский портал» | «Отозвать» у чужих ссылок; разрешения на приёмку, подпись, оплату | Отзывает ссылки «Демо-квартиры»; новые права дают гостю право принять этап |
| «Профиль» → блок исполнителя | «Заменить исполнителя» | Меняет назначение прямо на показе |
| «Деньги» | «Оплатить N ₽» (ЮKassa) | Платёжного провайдера нет, ответ 503 |
| «Деньги» → «Оплаты» | «Импорт выписки» | Нужен файл выписки; случайный файл создаст записи |
| «Приёмка» | «Вернуть на доработку» без подготовленной причины | Требует причину, откатывает этап |
| «Ремонт» → «Этапы» | долгое нажатие на строку этапа (массовая сдача) | Помечает этапы к сдаче |
| «Сообщения» | «Создать чат» на общем объекте | Копит служебные чаты |
| Терминал | `npm run dev -- reset` и `cleanup_e2e_demo_data.py --apply` во время показа | Первое сносит локальные тома, второе убирает проекты |
| Любой экран | действия с пометкой в тексте «необратимо» | Читайте окно подтверждения до нажатия |

Если на экране всплыла ошибка или спиннер висит дольше десяти секунд, не нажимайте всё подряд: закройте окно, нажмите «Повторить» или обновите страницу (`Cmd+R`) и продолжайте с того же шага.

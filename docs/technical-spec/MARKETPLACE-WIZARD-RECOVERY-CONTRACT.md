# Renova — восстановление мастера «Заявка → проект»

**Статус реализации:** IMPLEMENTED; CI VERIFIED только после успешных проверок точного коммита PR.  
**Дата:** 2026-09-08.  
**Родительское ТЗ:** [RENOVA-TECHNICAL-SPECIFICATION.md](../RENOVA-TECHNICAL-SPECIFICATION.md).  
**Связанный серверный контракт:** [PROJECT-PARTICIPANT-SCOPE-CONTRACT.md](PROJECT-PARTICIPANT-SCOPE-CONTRACT.md).  
**Владелец:** Renova mobile engineering. Общая многоподрядная задача #300 остаётся открытой.

## 1. Зафиксированные разрывы маршрута

Проверены `JobLeadsBoard.tsx`, `api/market.ts`, `contractor-wizard/[leadId].tsx`, `roomTypes.ts`, `RenovaContext.tsx` и серверная конвертация.

Доска направляет исполнителя в мастер для заявки `quoted`, но прежний мастер запрашивал `listJobLeads(user.id)` без статуса. Серверный статус по умолчанию — `open`; результат не содержал нужную заявку, а экран оставался на «Загрузка заявки…» без отдельного состояния отсутствия или ошибки.

Прежний мастер также объединял POST конвертации, обновление списка, загрузку проекта и навигацию в один catch. Поэтому сбой после подтверждённого POST показывался как неуспешное создание. Дополнительно мастер передавал вымышленный объект `{ id } as any` в глобальные побочные действия.

При проверке связанного контекста обнаружено: `loadProject()` может поглотить ошибку rate limit и завершиться без выбора проекта. Кроме того, для исполнителя этот метод вызывает совместимый `assignProject`; его нельзя описывать как чистое чтение.

## 2. Каноническая цепочка

`доска согласованных заявок → contractor-wizard/<leadId> → текущая роль исполнителя → явный GET status=quoted → точный leadId → комнаты/тип объекта → POST convert → подтверждённый project_id → обновление списка → loadProject(project_id) → проверка activeProject.id → переход на главную`.

Серверная авторизация, связь заявки с исполнителем, атомарность и идемпотентность принадлежат серверному контракту. PR #313 квалифицирован на `ae8a0750bb6cc788c9e93a1f85a7355f3b180380` и объединён как `65ddb7e59e6bcb23473b1017686cd3adbd882187`. Его 20 успешных проверок и специализированный прогон 35 тестов не заменяют проверки нового мобильного коммита.

Мобильный helper не создаёт второй источник истины: `loadQuotedLead` выбирает конкретную согласованную заявку; `openConvertedProject` выполняет восстановление по уже подтверждённому ID и вообще не принимает операцию конвертации.

## 3. Состояния экрана и восстановление

| Состояние | Поведение |
|---|---|
| loading | Индикатор только до завершения актуального запроса. |
| ready | Комнаты и тип объекта; одна основная кнопка создания. |
| error | Ошибка загрузки не выдаётся за отсутствие заявки; доступен повтор. |
| unavailable | Запрос завершился, но подходящая заявка недоступна; бесконечной загрузки нет. |
| conversion unconfirmed | Нет подтверждённого ответа POST; UI не утверждает ни создание, ни откат. Повтор должен сохранять параметры запроса. |
| project created | Ответ сервера сохранён до любых последующих операций; поля создания больше не показываются. |
| open failed / selection unconfirmed | Сохраняется состояние «Проект создан» и кнопка «Открыть созданный проект». Повтор не вызывает convertJobLead. |
| selected | Навигация только при совпадении текущего activeProject.id с подтверждённым project_id и актуальном контексте аккаунта/заявки. |

Ошибка обновления списка не препятствует попытке открыть сохранённый проект. Ошибка открытия и ошибка навигации учитываются отдельно от исходной мутации. `load_completed` означает только завершение вызова загрузчика, а не подтверждённый выбор объекта.

## 4. Защитные ограничения клиента

Синхронный `busyRef` блокирует повторное нажатие до перерисовки React; кнопка и поля отключаются на время запроса. Смена пользователя, роли или leadId сбрасывает черновик, сохранённый результат и состояние операции. Старые данные скрываются сразу, до выполнения эффекта сброса. Устаревший ответ загрузки игнорируется по идентичности контекста и номеру запроса.

Пустые названия комнат проверяются до POST; длина названия ограничена 100 символами, число комнат — 100. Текущие ROOM_PRESETS совместимы со структурированной серверной схемой. Расчёт предварительной оценки остаётся прежним и не подменяет подтверждённую серверную смету.

Мастер не вызывает syncProjectSideEffects с фиктивным объектом. Выбор проекта и распространение актуальных данных остаются у RenovaContext.loadProject. Используются общая Card, PrimaryButton и цвета темы; собственные hex-цвета удалены. Для изменённых интерактивных элементов заданы подписи доступности и минимальная высота 44.

## 5. Проверки

Существующий `jobLeadCreate.w140.test.ts` сохраняет прежние контракты доски и дополнен исполняемыми проверками helper:

- запрос именно quoted, точное совпадение ID/статуса, отсутствие и ошибка загрузки;
- порядок обновления/открытия сохранённого ID;
- продолжение открытия при сбое обновления списка;
- отдельный результат ошибки открытия и повтор по тому же ID без конвертации;
- остановка до запроса, после обновления и после загрузки при смене контекста;
- сохранение признака ошибки даже при Promise.reject(undefined).

Контракты исходного кода дополнительно проверяют сохранение ответа до восстановления, единственный защищённый вызов конвертации, блокировку двойного нажатия, отсутствие фиктивного контекста, сброс при смене аккаунта/заявки, использование выбранного ID перед навигацией и общих визуальных компонентов.

Требуются свежие mobile TypeScript/domain/runtime, полный применимый CI, Playwright и техническое ТЗ. Unit/source contracts и общий браузерный прогон не называются отдельным новым end-to-end тестом этого мастера на физическом устройстве. Такой точечный device/E2E сценарий остаётся отдельной приёмкой.

## 6. Явно сохранённые границы и следующие блокеры

**CONTEXT-IN-FLIGHT-FENCING — владелец Renova mobile engineering.** Общие refreshProjects/loadProject пока могут менять глобальный контекст из уже запущенного запроса после смены аккаунта. Защита данного экрана останавливает собственные обновления/навигацию и последующие вызовы, но не отменяет внутреннюю операцию общего контекста. Нужны общий session-generation fence и конкурентные тесты смены аккаунта во время чтения/совместимого назначения.

**COLD-START-CONVERSION-DISCOVERY — владелец Renova mobile engineering.** Подтверждённый ID хранится в состоянии текущего мастера, а не в новом постоянном журнале клиента. После перезапуска созданный объект доступен через список проектов; автоматическое восстановление мастера по уже taken-заявке требует отдельного авторизованного read-маршрута или согласованного механизма discovery. Этот PR не заявляет такую функцию реализованной.

**TARGETED-WIZARD-E2E — владелец Renova QA.** Добавить отдельный браузерный/устройственный сценарий: согласованная заявка → мастер → конвертация → искусственный сбой refresh/load → повтор открытия без второго POST; отдельно rate limit и смена аккаунта. Имеющиеся helper/source тесты не заменяют эту приёмку.

Оставшиеся LEGACY-WRITER-RETIREMENT, CONTRACTOR-CAPACITY-SERIALIZATION, MARKETPLACE-SOURCE-TRANSITIONS, независимые подрядчики и внешние операционные блокеры сохраняются в связанном серверном контракте. Общая готовность не меняется: `BLOCKED_FOR_BROAD_PRODUCTION`.

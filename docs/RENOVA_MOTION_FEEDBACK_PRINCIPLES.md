# Renova Motion and Feedback Principles

## Goal

Define how interface changes should communicate state and confidence.

## Motion principles

- Motion should explain change, not decorate.
- Transitions should preserve user context.
- Important state changes should feel intentional.
- Avoid unnecessary animation competing with work.

## Feedback patterns

### Success

Should confirm completion and show the updated state.

### Error

Should explain the issue and provide recovery.

### Loading

Should preserve layout and indicate progress.

### Destructive actions

Should communicate consequence before execution.

## Operational product rule

In a renovation management system, confidence and clarity are more important than visual effects.

## Review questions

- Did the user understand what changed?
- Did the interface reduce uncertainty?
- Was feedback proportional to the action?

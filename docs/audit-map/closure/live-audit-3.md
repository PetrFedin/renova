# Живой аудит 3 (headless Playwright, обе роли, 375/768/1280)

Среда: Expo web localhost:8081, backend 127.0.0.1:8100, проект «AUDIT3 Квартира» (свой, адрес «E2E audit3»). После прогона проект уходит в корзину/архив. Скриншоты вне репозитория (scratchpad).
Охват: путь исполнителя (главная, ремонт, бюджет, материалы, чат, профиль, команда/QR, портфель, подписка, заявки), денежный сценарий заказчика, гость, новые функции волн 9–11.

## Исправлено

### A3-01 (P2, исправлено) Сырые ISO-даты и суммы в нескольких местах
- Исполнитель: «Ремонт → Этапы» и «Гарантия» — строка этапа `— · 2026-10-06 · 5 542 ₽`; карточка этапа «План: 2026-10-03 → 2026-10-06» и «Срок доработки»; Приёмка («Срок доработки: …»); Контроль («до 2026-…»); Портал («План окончания»). Теперь `дд.мм.гггг` (`formatScheduleDayFull`).
- Лента активности: «2026-10-03 20:32» (UTC без пояса) → местное «03.10.2026 23:32» (`formatEventDateTime`).
- Чат, карточка задачи: «Задача: … · до 2026-10-05» → «до 05.10.2026» (backend `chat_service._ru_date`).
- Уведомления: тело «15000.0» («Доп. работы согласованы») → «15 000 ₽»; нормализация при записи и чтении (`normalize_notification_body`), для ленты активности добавлен вид `ChangeOrder*`.
- Активность «Создан объект»: «план: 110848.80 ₽» → «110 848,80 ₽».
- Тесты: `backend/tests/test_money_format.py` (2 новых), `apps/mobile/lib/auditThree.test.ts` (в `mobile:test`).

### A3-02 (P3, исправлено) Хлебная крошка экрана «Профиль» называлась «Данные объекта»
- `/profile` (аккаунт, «Выбор роли», код профиля) показывал крошку «Главная · Данные объекта»; «Данные объекта» — это вкладка Объект. `ROUTE_TITLES.profile` → «Профиль». Тест в `auditThree.test.ts`.

### A3-03 (P0, исправлено в коде; на живом стенде нужен перезапуск backend) `GET /projects` и `/projects/{id}` не отдавали `contractor_id`
- Симптом: у исполнителя на «Объект → Смета» кнопка «Отправить смету на согласование» всегда выключена (атрибут disabled); главный CTA главной «Отправить смету на согласование» ведёт на этот экран — отправить смету из приложения нельзя. Для заказчика `activeProject.contractor_id` тоже всегда пусто: «исполнитель не назначен» в Комнатах/Профиле/Выборе материалов, вывоз «своими силами», чек-лист настройки.
- Причина: `ProjectOut` не содержит `contractor_id`, а `isContractorOwner` (`RenovaContext`) и ~10 экранов проверяют именно его.
- Исправление: `contractor_id` в `ProjectOut` для `access_mode` owner/contractor (гостю, технадзору и независимому участнику — null, чтобы не раскрывать ведущего). Тест `test_connected_contractor_id_is_exposed_only_to_owner_and_lead`. Проверено в браузере подменой ответа (кнопка включается). uvicorn на :8100 запущен без `--reload` — перезапустить, чтобы увидеть живьём.

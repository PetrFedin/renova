# Renova Empty and Error State Principles

## Goal

Make non-ideal states useful instead of passive messages.

## Empty states

Rules:

- explain why the state exists;
- show the next useful action;
- avoid dead ends;
- keep the message concise.

Examples:

- no expenses -> explain how to add the first expense;
- no selections -> explain how to start selection;
- no issues -> show healthy state and related navigation.

## Error states

Rules:

- explain what happened;
- provide recovery path;
- preserve user context;
- avoid technical language.

## Loading states

Rules:

- communicate progress when possible;
- avoid layout jumps;
- keep primary task visible.

## Product principle

Every state should answer:

1. What happened?
2. What does it mean?
3. What should I do next?

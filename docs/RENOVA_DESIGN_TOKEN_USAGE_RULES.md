# Renova Design Token Usage Rules

## Goal

Prevent visual drift by keeping interface decisions centralized.

## Typography

Use shared typography roles instead of local one-off values.

Prefer:

- section hierarchy;
- list hierarchy;
- metric hierarchy;
- empty state hierarchy.

Avoid:

- custom font sizes for individual screens without reason;
- inconsistent weights for similar content.

## Spacing

Use predictable spacing patterns.

Avoid:

- arbitrary padding values;
- different spacing for identical components;
- dense controls mixed with large surfaces.

## Surfaces

Use elevation intentionally.

Rules:

- elevated surfaces highlight important decisions;
- operational content prefers lists and separators;
- nested cards should be avoided.

## Controls

Controls should follow shared behavior:

- buttons have clear hierarchy;
- chips are for filtering, not primary actions;
- confirmations are consistent.

## Principle

Tokens are not decoration. They are the operating rules that keep Renova feeling like one product.

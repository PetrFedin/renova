# Renova Polish Validation Checklist

## Visual system

- [ ] One primary CTA per surface
- [ ] Destructive actions use danger hierarchy
- [ ] Secondary actions use outline treatment
- [ ] Touch targets meet mobile baseline
- [ ] Sheets share common chrome

## Information architecture

- [ ] Summary before details
- [ ] Lists preferred over unnecessary cards
- [ ] Filters do not compete with actions
- [ ] Progressive disclosure for complex data

## Key surfaces

### Money

- [ ] Budget summary is decision-first
- [ ] Expense actions are clearly separated
- [ ] Payment flows have clear CTA priority

### Operations

- [ ] Rooms list is overview-first
- [ ] Materials avoid duplicated actions
- [ ] Portal matches in-app language

### Investor walkthrough

- [ ] First viewport explains value
- [ ] No dashboard overload
- [ ] Consistent visual rhythm

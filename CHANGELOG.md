# Changelog

Формат: Keep a Changelog. Версии до первого релиза в сторах были внутренними (тег `v0.2.0` ... `v0.3.7`). Номер первого публичного релиза назначает владелец продукта; исходники на дату записи несут `0.3.7` (`apps/mobile/app.json`, `/health.version`).

Статус внешних подключений и блокеров запуска ведётся в `PRODUCTION-READINESS.md`. Здесь только то, что изменилось в коде.

В main после `v0.3.7` вошло около 920 коммитов: исправлений (около 330), тестов (около 100), документов, новых возможностей (около 65), рефакторинга и CI. Ниже — по областям; это не полный список, источник правды — `git log v0.3.7..main`.

### Добавлено

- **Участники проекта и подрядчики:** заявка исполнителя с подтверждением заказчиком, замена и снятие исполнителя; основа для нескольких подрядчиков, управление участниками, атомарная конвертация заявки (lead) в проект. Полный сценарий независимого подрядчика не завершён.
- **Маркетплейс:** жизненный цикл заявок, русские статусы, фильтры и пагинация ленты, приватные ветки по заявке, причина закрытия (миграция `x06`).
- **Чат:** атомарная идемпотентная запись сообщений, правка и удаление сообщений, переименование и архив ветки, выход и удаление участников, доставка приглашений по SMS через outbox.
- **Платежи:** ручные подтверждения оплаты (загрузка и проверка доказательств с историей), планы платежей по этапам, спор по платежу и ответ подрядчика, счёт по допработам (change order) с привязкой к этапу.
- **Закупки и материалы:** сквозная модель поставки материалов с учётом количества, правда о ценах (происхождение, карантин), правка и удаление выбора материала, отзыв согласования.
- **Этапы и приёмка:** атомарные сдача и доработка, канонические переходы проверки, пересмотр подтверждённого графика работ, решение заказчика по продлению срока доработки, технадзор закрывает замечания.
- **Комнаты и сметы:** запрос на добавление комнаты и на изменение после подключения исполнителя; экспорт сметы с НДС проекта.
- **Уведомления:** центр уведомлений с колокольчиком и счётчиком; push через outbox, привязка и отвязка токена, переходы по ролям.
- **Аккаунт:** удаление аккаунта в профиле с проверкой блокирующих условий, отзыв ссылок портала.
- **Операции:** консоль восстановления dead-letter outbox, алерты об ухудшении outbox, worker heartbeat, отдельный процесс `renova-worker`.
- **Провайдеры:** реестр портов `payment`/`fiscal_receipt`/`npd_status`/`sms`/`push` с режимами `off|simulated|real`; `simulated` запрещён в staging/production.
- **Релизная подготовка:** `scripts/release-smoke.py` (сквозной smoke критического пути), `docs/RELEASE-RUNBOOK.md`, `docs/BACKUP-POLICY.md`, полный шаблон `backend/.env.production.example`.

### Изменено

- Миграции `x06`..`x08`: схема моделей и Alembic выровнена (NOT NULL, внешние ключи, индексы); ratchet дрейфа схемы ведётся от базовой линии 0 (`backend/scripts/schema_drift_baseline.json`).
- Безопасность: пустой `ENVIRONMENT` трактуется как production; в рабочих средах запрещены demo-seed, `create_all`, вход по заголовку user id, SQLite и слабые ключи; Redis обязателен для OTP и rate limit; ограничение запросов не пропускает трафик при недоступном Redis.
- Мобильные экраны: честные состояния загрузки, пустоты и ошибок, подписи доступности и области нажатия 44 px, защита навигации от внешних `returnTo`, показ ошибок решений вместо тихого игнорирования.
- Хранилище: нет тихого отката S3 на локальный диск; частичная конфигурация S3 — ошибка.
- CI: добавлены ratchet типов mobile (real = 0), тесты calc-engine, job регресса жизненного цикла, ratchet дрейфа схемы, контракт локального runtime, проверка worker heartbeat (`.github/workflows/worker-runtime-integrity.yml`).

### Исправлено

Сотни исправлений по итогам аудита экранов и сквозных сценариев (идентификаторы вида `SCR-`, `HOM-`, `OBJ-`, `REP-`, `BUD-`, `INB-`, `MKT-`, `COM-`, `EST-`, `JRN-`, `APIA-`, `APIB-` в сообщениях коммитов); таблицы закрытия — `docs/audit-map/closure/`. Среди них: дублирование проекта при повторе, расхождение процента прогресса, потеря полей при слиянии офлайн-очереди, подтверждение платежа без перевода, обход ACL в чате и вложениях, видимость платёжных реквизитов гостю.

### Известные ограничения

Не закрыто и не должно подаваться как работающее: боевые ЮKassa/«Мой налог»/Twilio/push не проверены с реальными ключами; Госключ не реализован; OCR работает по метаданным, а не по содержимому; повтор после потерянного ответа для части офлайн-операций может задвоить действие (#316); подробности и владельцы — `PRODUCTION-READINESS.md`.
